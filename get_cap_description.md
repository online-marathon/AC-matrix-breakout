Команда **`getcap -r / 2>/dev/null`** є одним із найважливіших інструментів, які використовуються під час аудиту безпеки систем Linux, тестування на проникнення (пентесту) та підняття привілеїв (Privilege Escalation).

Давайте розберемо детально саму команду, концепцію, на якій вона базується, та її значення для кібербезпеки.

---

### 1. Анатомія команди (що означає кожен елемент)

* **`getcap`** (Get Capabilities) — це утиліта, яка відображає файлові можливості (capabilities) для зазначених файлів або директорій.
* **`-r`** (Recursive) — прапорець, який змушує команду працювати рекурсивно, тобто перевіряти не лише вказану папку, а й усі її підпапки та файли всередині.
* **`/`** — корінь системи. Вказує, що пошук потрібно почати з самого верху файлової системи Linux і перевірити абсолютно всі файли на диску.
* **`2>/dev/null`** — перенаправлення потоку помилок (`stderr`). Оскільки команда сканує весь диск, вона неминуче спробує отримати доступ до системних папок, куди у звичайного користувача немає прав (наприклад, `/root`). Щоб екран не засмічувався сотнями рядків повідомлень *"Permission denied"* (Доступ заборонено), усі помилки тихо відправляються в "чорну діру" Linux — `/dev/null`.

**Загальний зміст команди:** *«Знайди та покажи мені всі файли в системі, які мають особливі файлові можливості, і не показуй мені помилки доступу».*

---

### 2. Контекст кібербезпеки: Що таке Linux Capabilities?

Історично в Linux був суворий поділ: або ти звичайний користувач (Unprivileged), або всемогутній `root` (Privileged). Якщо звичайній програмі (наприклад, утиліті `ping`) потрібно було надіслати спеціальний мережевий пакет, їй доводилося давати повні права суперкористувача через механізм **SUID** (Set User ID). Якщо в такій програмі знаходили вразливість, зловмисник миттєво отримував повний контроль над усією системою.

Щоб вирішити цю проблему, в ядро Linux впровадили **Capabilities (Можливості)**. Вони розділяють величезну владу `root` на десятки маленьких, ізольованих дозволів.

Наприклад:

* `CAP_NET_RAW` — дозволяє лише відкривати сирі мережеві сокети (потрібно для `ping` або `tcpdump`), але не дозволяє читати чужі файли.
* `CAP_SETUID` — дозволяє програмі змінювати ідентифікатор користувача (UID).
* `CAP_DAC_OVERRIDE` — дозволяє обходити перевірку прав доступу до файлів (читати/писати будь-який файл у системі).

---

### 3. Чому ця команда критична для кібербезпеки?

Для системного адміністратора (Блакитна команда / **Blue Team**) та хакера/пентестера (Червона команда / **Red Team**) ця команда має протилежне, але однаково важливе значення.

#### Атака (Підняття привілеїв / Privilege Escalation)

Коли хакер отримує початковий доступ до сервера Linux, він зазвичай заходить під обліковим записом з низькими правами (наприклад, `www-data` від вебсервера). Його мета — стати `root`.

Запустивши `getcap -r / 2>/dev/null`, атакуючий шукає **небезпечно налаштовані бінарні файли**. Якщо адміністратор помилково або для зручності видав потужну можливість звичайній утиліті, хакер використає її для захоплення системи.

**Приклади небезпечних знахідок (Вектори атаки):**

1. **Якщо знайдено `tar` або `python` з можливістю `cap_dac_override+ep`:**
Це означає, що за допомогою цієї копії тар-архіватора або інтерпретатора Python можна прочитати або перезаписати *будь-який* файл у системі, ігноруючи обмеження. Хакер може просто прочитати файл `/etc/shadow` із хешами паролів усіх користувачів або записати свого користувача у `/etc/passwd`.
2. **Якщо знайдено `perl` або `python` з можливістю `cap_setuid+ep`:**
Зловмисник може запустити короткий скрипт, який підмінить поточний UID процесу на `0` (UID рута) і запустить командну оболонку `/bin/sh`. Результат — миттєвий root-доступ.
```bash
# Приклад експлуатації для python:
python -c 'import os; os.setuid(0); os.system("/bin/bash")'

```


3. **Якщо знайдено `gdb` (налагоджувач) або `strace` з можливістю `cap_sys_ptrace+ep`:**
Хакер може підключитися до будь-якого запущеного процесу (наприклад, до процесу SSH-сервера або менеджера автентифікації) і витягнути з його оперативної пам'яті паролі користувачів у відкритому вигляді.

#### Захист (Аудит системи / Hardening)

Системні адміністратори та офіцери з кібербезпеки запускають цю команду під час регулярного аудиту безпеки.

* Отриманий список порівнюється з еталонним (стандартним для чистої ОС).
* Якщо виявляються сторонні програми (особливо інтерпретатори мов програмування, архіватори чи текстові редактори), які мають встановлені capabilities, це розцінюється як критична вразливість конфігурації (**Misconfiguration**).
* Адміністратор має негайно видалити небезпечну можливість за допомогою команди `setcap -r /шлях/до/файлу`.

### Підсумок

Команда `getcap -r / 2>/dev/null` — це стандартний крок у будь-якому чек-листі з аналізу безпеки Linux. Вона підсвічує приховані привілеї у системі, які розробники або адміністратори залишили для роботи програм, але які можуть бути використані як "трамплін" для отримання повних прав суперкористувача.

---

Ці знахідки в межах CTF (Capture The Flag) або тестування на проникнення є класичним вектором для **підняття привілеїв (Privilege Escalation)** з рівня звичайного користувача до рівня суперкористувача (`root`).

Ось детальний розбір того, про що свідчить кожен рядок і як це використовувати для захоплення прапора:

---

### 1. Головна знахідка: `/home/cyber/tar cap_dac_read_search=ep`

**Це ваш ключ до рута (Critical Vulnerability / Misconfiguration).**

* **Що це означає:** Хтось створив копію стандартного архіватора `tar` у домашній директорії користувача `cyber` і надіслав їй особливу можливість — `cap_dac_read_search`.
* **Чому це небезпечно:** Прапорець `cap_dac_read_search` дозволяє програмі повністю ігнорувати перевірки прав доступу на **читання файлів та пошук у директоріях**. Цей файл `tar` тепер може прочитати будь-який файл у системі, навіть якщо він належить `root` і має права `chmod 600`.
* **Як це експлуатувати (Вектор атаки):**
Ви можете використати цей `tar`, щоб заархівувати чутливі системні файли (наприклад, приватні SSH-ключі рута або файл із хешами паролів), а потім розпакувати їх у свою папку, де ви вже зможете їх вільно прочитати.
*Крок 1. Архівуємо файл із паролями системи за допомогою вразливого tar:*
```bash
/home/cyber/tar -cvf /tmp/shadow.tar /etc/shadow
```

*Крок 2. Розпаковуємо його у свою директорію `/tmp`:*
```bash
/home/cyber/tar -xvf /tmp/shadow.tar -C /tmp/
```


Тепер ви можете просто виконати `cat /tmp/etc/shadow`, отримати хеш пароля користувача `root` та спробувати підібрати його через *John the Ripper* або *Hashcat*. Також ви можете спробувати у такий же спосіб вкрасти прапор CTF (наприклад, якщо він лежить у `/root/flag.txt`).

---

### 2. Друга знахідка: `/usr/bin/ping cap_net_raw=ep`

**Це абсолютно нормальна, легітимна конфігурація (Intended Behavior).**

* **Що це означає:** Утиліта `ping` має можливість `cap_net_raw`, яка дозволяє їй створювати "сирі" (raw) мережеві сокети для надсилання ICMP-пакетів.
* **Чому вона тут:** У сучасних дистрибутивах Linux це стандартний підхід до безпеки. Раніше, щоб `ping` працював, йому давали повні права через SUID (`chmod +s`). Тепер замість повних прав рута йому дають лише одну цю маленьку можливість.
* **Чи можна це експлуатувати для Privilege Escalation:** Ні, у цьому конкретному випадку для підняття прав утиліта `ping` вам нічим не допоможе. Це "хибний слід" (rabbit hole), на який не варто витрачати час під час виконання цього CTF-завдання.

### Загальний висновок для вашого CTF

Творці цієї віртуальної машини навмисно залишили вразливість у бінарнику `/home/cyber/tar`. Ваша стратегія для отримання максимальних привілеїв:

1. За допомогою `/home/cyber/tar` прочитайте файл `/etc/shadow` (для брутфорсу паролів) або перевірте наявність приватних ключів у `/root/.ssh/id_rsa`.
2. Якщо прапор CTF лежить у папці `/root/`, ви можете просто заархівувати його цим `tar` і розпакувати у `/tmp`, щоб прочитати текст прапора безпосередньо.
