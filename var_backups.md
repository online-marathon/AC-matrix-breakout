Вибір директорії **/var/backups/** під час проведення аудиту безпеки, тестування на проникнення (пентесту) або виконання CTF-завдань є логічним, обґрунтованим та високоефективним кроком.

Коли спроба брутфорсу (зламу) файлу `/etc/shadow` за допомогою *John the Ripper* завершується невдачею (наприклад, через занадто складний пароль або використання стійких сучасних алгоритмів хешування на кшталт `yescrypt` чи `argon2`), дослідник безпеки переходить до стратегії **пошуку чутливих даних у відкритому тексті (Cleartext Credentials Discovery)**.

Ось детальне розв'язання та технічне обґрунтування того, чому саме `/var/backups/` стає першочерговою ціллю для аналізу за наявності можливості `cap_dac_read_search`:

---

### 1. Стратегічне значення директорії `/var/backups/` у Linux

Згідно зі стандартами файлової системи Linux (FHS — Filesystem Hierarchy Standard), директорія `/var/backups/` призначена для зберігання резервних копій ключових системних даних, конфігурацій та логів.

Системні адміністратори або автоматизовані утиліти (наприклад, плани архівації `cron`) часто створюють там копії критичних файлів. Для атакуючого або аудитора це місце є **«золотою жилою»**, оскільки:

* **Там зберігається історія:** Навіть якщо поточний робочий конфігураційний файл надійно захищений або змінений, стара резервна копія може містити паролі, які все ще підходять до системи.
* **Там часто "забувають" тимчасові файли:** Скрипти бекапу можуть створювати проміжні незашифровані `.bak`, `.tar`, `.sql` або `.old` файли з паролями, які згодом не видаляються.

### 2. Чому саме цей крок ефективний у поєднанні з `cap_dac_read_search`

Оскільки утиліта `tar` у вашій системі має привілей `cap_dac_read_search+ep`, вона здатна ігнорувати перевірку прав доступу на читання (`read`) та перегляд папок (`search`).

1. **Обхід обмежень файлової системи:** За звичайних умов файл `/var/backups/.old_pass.bak` закритий від перегляду (має права на кшталт `chmod 600` і належить власнику `root`). Звичайний користувач навіть не дізнається про його існування, якщо права на саму директорію `/var/backups/` обмежені.
2. **Аналіз прихованих файлів:** Крапка перед назвою файлу (`.old_pass.bak`) робить його прихованим у Linux. Адміністратори часто використовують приховування як наївний засіб захисту («безпека через обскурацію» — *Security through obscurity*). Проте використання `tar` з повноваженнями обходу DAC дозволяє безперешкодно заархівувати цю директорію разом із прихованими об'єктами.

### 3. Технічний розбір ланцюжка експлуатації

Наведений вами алгоритм дій демонструє правильну послідовність дій для підвищення привілеїв:

1. **Створення архіву (Архівація під привілеями):**
```bash
./tar -cf password.tar /var/backups/.old_pass.bak

```


Вразливий локальний бінарник `./tar` використовує свою системну можливість `cap_dac_read_search`, заходить у захищену директорію, зчитує вміст заблокованого для звичайних користувачів файлу `.old_pass.bak` і пакує його у звичайний файл `password.tar`. Оскільки цей новий архів створює поточний користувач, права на сам архів `password.tar` належать саме йому.
2. **Розпакування (Зміна контексту прав):**
```bash
tar -xf password.tar

```


При розпакуванні архіву стандартною утилітою `tar` (вже без привілеїв рута) файли видобуваються у поточну робочу директорію користувача. Навіть якщо оригінальний файл мав суворі обмеження, розпакована копія стає доступною для читання поточному користувачу.
3. **Отримання результату:**
```bash
cat .old_pass.bak

```


Читання незашифрованого пароля з файлу дає змогу виконати команду `su root` або авторизуватися через SSH під вищими привілеями, успішно завершуючи атаку чи аудит.

### Резюме

Вибір `/var/backups/` — це демонстрація високої кваліфікації дослідника. Замість того, щоб витрачати години чи дні на безуспішний перебір (брутфорс) стійких криптографічних хешів із `/etc/shadow`, дослідник використав логічний пошук слабких місць конфігурації у файловій системі, де з високою ймовірністю залишаються текстові залишкові дані (Data Remnants) адміністративних копій.
